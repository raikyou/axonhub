# Context Manager 设计总结

## 目标

统一管理 Agent 会话上下文：

- 消息管理从 Agent 解耦，支持可替换实现
- 支持叠加上下文策略（压缩、跨线程摘要、token 统计）
- 支持跨重启持久化

## 核心能力

- 消息读写与清理
- 推理前上下文准备（可触发压缩、注入摘要）
- 用量统计记录
- 状态快照与持久化

## Thread 语义

每个 Thread 独立维护消息历史和摘要。未指定时使用默认 Thread。

## 实现策略

### SimpleContextManager

- 纯内存存储，按 Thread 隔离
- 不做压缩，透传历史
- 作为默认实现或其他策略的底座

### PersistentContextManager

装饰器模式，可嵌套组合多层策略。

**压缩触发条件**：
- 消息 token 总量超过软阈值（默认 120k）
- 且消息数超过保留数量的一半

**压缩策略**：
- 保留最近 N 条消息（默认 80 条）
- 被裁剪的历史生成摘要，追加到 Thread 摘要中
- 摘要格式为角色标注的文本截断，限制总长度

**跨 Thread 摘要**：
- 每次推理前，从其他最近活跃的 Thread 提取摘要
- 作为系统消息注入，提供跨会话上下文
- 可配置注入数量（默认 2 个 Thread）

**持久化内容**：
- 各 Thread 的摘要与压缩次数
- 全局与 Thread 级 token 累计
- Thread 访问顺序（用于跨 Thread 摘要选择）

## 组合方式

通过装饰器嵌套，外层策略在内层结果上执行，灵活组合多种行为。

## Token 估算

针对多语言优化：

- ASCII/Latin：约 4 字符/token
- CJK（中日韩）：约 1.5 字符/token

用于触发压缩，非精确计费。

## 当前边界

- 摘要为规则化截断，不依赖额外模型
- 策略链按嵌套顺序执行，需调用方保证组合合理
